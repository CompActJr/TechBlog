Etapa 01 de 11

Como a Web funciona

O que é?

A web (World Wide Web) é um sistema de documentos interligados por links que roda sobre a internet — a rede física que conecta computadores no mundo todo. A comunicação acontece no modelo cliente-servidor: o navegador (cliente) pede informações e o servidor (um computador que guarda e entrega sites) responde.

O que você precisa entender

  • Internet ≠ Web: a internet é a rede; a web é uma das aplicações que usam essa rede (assim como e-mail e mensagens).
  • Cliente e servidor: o navegador solicita, o servidor entrega.
  • Recursos: páginas, imagens, vídeos e APIs são recursos identificados por um endereço (URL).

Como funciona?

  1. Você digita um endereço (URL) no navegador.
  2. O navegador pergunta ao DNS qual é o número (IP) daquele nome.
  3. Ele envia uma requisição HTTP ao servidor.
  4. O servidor localiza o recurso e devolve a resposta (HTML, CSS, JS, imagens...).
  5. O navegador interpreta e renderiza a página para você.
Você digita uma URL no navegador
        │
        ▼
[Navegador] ── "qual é o IP de site.com?" ──► [Servidor DNS]
        │                                          │
        │◄──── devolve o IP (192.168.0.1) ────────┘
        ▼
[Navegador] ── envia requisição HTTP ──► [Servidor Web]
        │                                          │
        │◄── devolve HTML + CSS + JS ─────────────┘
        ▼
[Navegador] interpreta e renderiza a página

Onde isso aparece?

Em toda vez que você abre um site, envia um formulário ou assiste a um vídeo. Quando um site "não carrega", o motivo costuma estar em uma destas peças: DNS, rede, servidor ou navegador — agora você sabe onde procurar.

Etapa 02 de 11

URL, DNS, HTTP e HTTPS

O que é?

A URL é o endereço de um recurso na web. O DNS traduz nomes (como site.com) em endereços numéricos (IP) — a "agenda telefônica" da internet. O HTTP é o protocolo de comunicação entre cliente e servidor, e o HTTPS é a versão segura, com os dados cifrados.

O que você precisa entender

  • As partes de uma URL: protocolo, domínio, caminho, query string.
  • Os métodos HTTP: GET (buscar), POST (criar), PUT (atualizar), DELETE (remover).
  • Os códigos de status: 200 (ok), 301/302 (redirecionamento), 404 (não encontrado), 500 (erro do servidor).
  • HTTPS = HTTP + cifragem (SSL/TLS): é por isso que existe o "cadeado" na barra de endereço.

Como funciona?

  1. Você digita https://www.site.com/blog/artigo.
  2. O navegador consulta o DNS e descobre o IP do domínio.
  3. Ele envia uma requisição GET /blog/artigo ao servidor.
  4. O servidor responde com 200 OK e o conteúdo — ou com um erro, como 404.
  5. Como é HTTPS, tudo isso viaja cifrado.
https://www.site.com:443/blog/artigo?pagina=2#topo
│      │            │   │             │        │
│      │            │   │             │        └ ancoragem (#topo)
│      │            │   │             └ query string (?pagina=2)
│      │            │   └ caminho (/blog/artigo)
│      │            └ porta (:443, padrão HTTPS)
│      └ domínio (www.site.com)
└ protocolo (https://)

Códigos de status mais comuns:
200 OK · 301 Movido · 404 Não encontrado · 500 Erro do servidor

Onde isso aparece?

No cadeado de HTTPS ao lado do endereço, nos erros de página (404), nos links que você copia e compartilha e em tudo que um formulário envia para um servidor.

Etapa 03 de 11

HTML — a estrutura

O que é?

HTML (HyperText Markup Language) é a linguagem de marcação que estrutura o conteúdo da web. Não é uma linguagem de programação: ela apenas descreve o que cada parte representa — títulos, parágrafos, imagens, links, listas e formulários.

O que você precisa entender

  • Tags e atributos: a maioria vem em par de abertura/fechamento: <tag atributo="valor">conteúdo</tag>.
  • Aninhamento: elementos podem conter outros elementos (pai e filho).
  • Semântica: tags como <header>, <nav> e <article> dão significado, não apenas forma.
  • DOM: o navegador transforma o HTML em uma árvore de objetos chamada DOM.

Como funciona?

  1. Você escreve o documento .html com tags.
  2. O navegador lê o arquivo de cima para baixo e monta o DOM.
  3. Ele aplica os estilos (CSS) e o comportamento (JS) sobre essa árvore.
  4. Você vê o resultado renderizado na tela.
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <title>Minha primeira página</title>
  </head>
  <body>
    <h1>Olá, mundo!</h1>
    <p>Este é o <strong>primeiro parágrafo</strong>.</p>
    <a href="https://developer.mozilla.org/pt-BR/">Estude no MDN</a>
    <img src="https://picsum.photos/200/120" alt="Imagem aleatória">
  </body>
</html>

Onde isso aparece?

Em todo site. Aperte F12 em qualquer página e abra a aba "Elements"/"Elementos" para ver o HTML vivo que o navegador montou.

Etapa 04 de 11

CSS — o estilo

O que é?

CSS (Cascading Style Sheets) é a linguagem de estilo da web. Ela controla cores, fontes, espaçamentos e posições, deixando o conteúdo do HTML com a aparência desejada.

O que você precisa entender

  • Regras: seletor { propriedade: valor; } — ex.: h1 { color: blue; }.
  • Seletores: por tag (p), classe (.card) ou id (#menu).
  • Box model: todo elemento é uma caixa com conteúdo, padding, borda e margem.
  • Cascata e especificidade: regras mais específicas "vencem" regras mais gerais.

Como funciona?

  1. Você define regras em um arquivo .css.
  2. O navegador combina cada seletor com os elementos do DOM.
  3. Ele calcula o estilo final (aplicando cascata e especificidade).
  4. Renderiza cores, fontes e layout na tela.
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <title>Exemplo CSS</title>
    <style>
      .card {
        width: 240px;
        padding: 1rem;
        border: 2px solid #00a7db;
        border-radius: 12px;
        font-family: sans-serif;
      }
      .card h2 { color: #1c314c; }
    </style>
  </head>
  <body>
    <div class="card">
      <h2>Um cartão</h2>
      <p>Estilizado com CSS.</p>
    </div>
  </body>
</html>

Onde isso aparece?

Em tudo que é visual em um site: cores, fontes, botões, espaçamentos, alinhamento e animações.

Etapa 05 de 11

JavaScript — a interatividade

O que é?

JavaScript é a linguagem de programação da web que roda dentro do navegador. Ela dá comportamento às páginas: reage a cliques, valida formulários, busca dados e altera o conteúdo sem recarregar a página.

O que você precisa entender

  • Variáveis guardam valores; funções agrupam lógica reutilizável.
  • Eventos (como click) disparam ações.
  • DOM: com document.querySelector você localiza e altera elementos.
  • O console do navegador (console.log) ajuda a depurar.

Como funciona?

  1. O navegador carrega o arquivo .js (ou o script embutido).
  2. O código registra listeners de eventos nos elementos do DOM.
  3. Quando o usuário interage (clica, digita), o evento dispara a função.
  4. A função altera o DOM e a tela é atualizada — sem recarregar a página.
let contador = 0;
const botao = document.querySelector('#botao');
const texto = document.querySelector('#texto');

botao.addEventListener('click', () => {
  contador += 1;
  texto.textContent = 'Você clicou ' + contador + ' vez(es).';
});

Onde isso aparece?

Em menus, carrosséis, validações de formulário, contadores e praticamente toda interação que não recarrega a página.

Etapa 06 de 11

HTML + CSS + JS juntos

O que é?

Os três pilares trabalhando juntos: o HTML define a estrutura, o CSS a aparência e o JavaScript o comportamento. É assim que se constrói qualquer aplicação web real.

O que você precisa entender

  • Separação de responsabilidades: cada linguagem cuida de uma parte do todo.
  • O JS manipula o DOM: cria, altera e remove elementos do HTML.
  • Eventos conectam tudo: o clique do usuário (HTML) é estilizado (CSS) e tratado (JS).

Como funciona?

  1. O HTML entrega a estrutura inicial (ex.: um formulário).
  2. O CSS deixa essa estrutura bonita e organizada.
  3. O JS escuta o evento (ex.: "Adicionar") e atualiza o DOM.
  4. O resultado aparece na tela sem recarregar a página.
<!-- Lista de tarefas: HTML + CSS + JS -->
<input id="tarefa" type="text" placeholder="Nova tarefa">
<button id="adicionar">Adicionar</button>
<ul id="lista"></ul>

<style>
  #tarefa { padding: .4rem; margin-right: .5rem; }
  #lista li { margin-top: .3rem; color: #1c314c; }
</style>

<script>
  const adicionar = document.getElementById('adicionar');
  const tarefa = document.getElementById('tarefa');
  const lista = document.getElementById('lista');

  adicionar.addEventListener('click', () => {
    if (!tarefa.value.trim()) return;
    const item = document.createElement('li');
    item.textContent = tarefa.value;
    lista.appendChild(item);
    tarefa.value = '';
  });
</script>

Onde isso aparece?

Em qualquer página interativa moderna: apps de tarefas, carrinhos de compra, timelines, formulários com validação instantânea.

Próxima etapa: Responsividade
Etapa 07 de 11

Responsividade

O que é?

Um site responsivo se adapta ao tamanho da tela — do celular ao monitor grande. Hoje é requisito básico: a maior parte do tráfego web vem de dispositivos móveis.

O que você precisa entender

  • Viewport: a área visível do navegador no dispositivo.
  • Media queries: regras CSS que valem só para certas larguras de tela.
  • Unidades relativas: %, rem, vw/vh em vez de valores fixos.
  • Flexbox e Grid: layouts que reorganizam os elementos sozinhos.

Como funciona?

  1. Você declara a viewport no HTML.
  2. No CSS, usa flexbox/grid e unidades relativas.
  3. Acrescenta media queries para ajustar o layout em telas pequenas.
  4. O navegador aplica as regras conforme o tamanho da tela.
<!-- No <head> do documento -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">

/* No CSS */
.container {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.card { flex: 1 1 240px; }

@media (max-width: 600px) {
  .card { flex-basis: 100%; }  /* empilha em telas pequenas */
}

Onde isso aparece?

Abra qualquer site moderno no celular e no desktop: menu vira hambúrguer, colunas empilham, imagens redimensionam. Tudo isso é responsividade.

Etapa 08 de 11

O que é Front-end

O que é?

Front-end é a parte da aplicação que o usuário vê e com a qual interage — tudo que roda no navegador. O back-end é a parte que roda no servidor (banco de dados, regras de negócio, autenticação). Os dois conversam via HTTP.

O que você precisa entender

  • Front-end = navegador (HTML, CSS, JS); back-end = servidor.
  • Frameworks front-end (React, Vue, Angular) existem para organizar e escalar interfaces — você não precisa aprendê-los agora, mas saberá por que existem.
  • Um desenvolvedor full-stack atua nas duas pontas.

Como funciona?

  1. O usuário abre a página: o front-end carrega no navegador.
  2. Quando precisa de dados, o front-end faz uma requisição ao back-end.
  3. O back-end consulta o banco, processa e devolve os dados.
  4. O front-end recebe e renderiza o resultado na tela.
        [ FRONT-END ]                 [ BACK-END ]
    roda no navegador                 roda no servidor
   HTML + CSS + JS             regras de negócio + banco de dados
        │                                  │
        └──────── requisição HTTP ────────►│
        │◄──────── resposta (JSON) ───────┘
        │
   renderiza para o usuário

Onde isso aparece?

É o que você está aprendendo nesta trilha. Esta própria página é um front-end — quando a CompActJr publica um site ou dashboard, o que o cliente vê é o front-end.

Etapa 09 de 11

APIs e comunicação

O que é?

Uma API (Interface de Programação de Aplicações) é a ponte que permite dois sistemas conversarem. Na web, as APIs REST expõem endpoints (URLs) que respondem dados em JSON — o formato de texto que todos os sistemas entendem.

O que você precisa entender

  • Endpoints: URLs que representam recursos (ex.: /usuarios).
  • Métodos HTTP: GET busca, POST cria, PUT atualiza, DELETE remove.
  • JSON: { "chave": "valor" } — como os dados trafegam.
  • Consumo: no navegador, usamos fetch() para buscar dados de uma API.

Como funciona?

  1. Seu código chama fetch('https://api.site.com/usuarios').
  2. O navegador envia uma requisição GET ao endpoint.
  3. A API processa e responde com um 200 e o corpo em JSON.
  4. Você converte (res.json()) e manipula os dados no JavaScript.
const url = 'https://api.github.com/users/compactjr';

fetch(url)                       // 1. faz a requisição GET
  .then(res => res.json())       // 2. converte a resposta em JSON
  .then(dados => {
    console.log(dados.login, dados.public_repos); // 3. usa os dados
  })
  .catch(erro => console.error(erro));

Onde isso aparece?

Em previsão do tempo, cotações, login com redes sociais, mapas e pagamentos — sempre que um site usa dados de outro serviço, há uma API por trás.

Etapa 10 de 11

Do código à aplicação

O que é?

Escrever código no seu computador é só o começo. Para virar um site acessível a todos, o projeto precisa ir para um servidor: é o deploy ou publicação. Isso envolve hospedagem (onde os arquivos ficam) e domínio (o endereço público).

O que você precisa entender

  • Hospedagem: o servidor que armazena e entrega os arquivos do site.
  • Domínio: o nome que as pessoas digitam (www.suaempresa.com.br).
  • Deploy: o ato de publicar uma nova versão do código no servidor.
  • Conceitos de CI/CD e DevOps vêm depois — aqui basta entender o fluxo.

Como funciona?

  1. Você desenvolve o site localmente.
  2. Publica os arquivos na hospedagem (painel da empresa, FTP ou Git).
  3. Aponta o domínio para a hospedagem (via DNS).
  4. Quando alguém acessa o domínio, o servidor entrega o site.
Seu computador ──► Hospedagem (servidor) ──► Internet
   (código)          │                           │
                     │ guarda os arquivos        │
                     ▼                           ▼
              Domínio: www.suaempresa.com.br ──► usuários acessam

Passos: código ─► publicar/deploy ─► domínio apontando ─► site no ar

Onde isso aparece?

Quando a CompActJr publica um site da empresa, quando você sobe um portfólio no GitHub Pages ou em qualquer serviço de hospedagem. Cada nova versão publicada é um deploy.

Glossário rápido

Os termos que você viu ao longo da trilha, em um só lugar.

URL
Endereço de um recurso na web, como https://site.com/pagina.
DNS
Sistema que traduz nomes de domínio em endereços de IP.
IP
Endereço numérico que identifica um computador na rede.
HTTP / HTTPS
Protocolo de comunicação web; HTTPS é a versão cifrada e segura.
Servidor
Computador que guarda e entrega sites e dados na internet.
Cliente
Programa que consome recursos, como o navegador.
HTML
Linguagem de marcação que estrutura o conteúdo da página.
CSS
Linguagem de estilo que controla a aparência da página.
JavaScript
Linguagem de programação que dá comportamento às páginas.
DOM
Árvore de objetos que o navegador monta a partir do HTML.
Tag
Marcador do HTML que define um elemento, como <p>.
Atributo
Informação extra de uma tag, como href ou src.
Seletor
Padrão do CSS que escolhe quais elementos serão estilizados.
Media Query
Regra CSS que se aplica conforme o tamanho da tela.
Responsivo
Site que se adapta a diferentes tamanhos de tela.
API
Interface que permite dois sistemas se comunicarem.
JSON
Formato de texto usado para trocar dados entre sistemas.
Front-end
Parte da aplicação que roda no navegador, o que o usuário vê.
Back-end
Parte que roda no servidor: banco de dados e regras de negócio.
Hospedagem
Serviço que armazena e entrega os arquivos de um site.
Domínio
Nome público de um site, como suaempresa.com.br.
Deploy
Ato de publicar uma nova versão do código no servidor.
Framework
Conjunto de ferramentas que acelera o desenvolvimento de apps.
